01 — The Opportunity

Why this, why now

The resume-tool market is large, proven, and — critically — consolidating around all-in-one workflows. Users are tired of stitching four subscriptions together (a scanner, a builder, a tracker, a cover-letter tool) and paying $60–100/month for the privilege of copy-pasting between tabs. That fatigue is the wedge.

The gap nobody owns Every major tool is built US-English first. None handle the Gulf CV format (photo, nationality, visa status, driving licence), Arabic/French output, UAE–KSA–Qatar job feeds, WhatsApp alerts, or AED pricing. You live in Sharjah, you're bilingual FR/EN, and you already run a francophone audience. This is a moat you can defend and larger players won't bother chasing.

Two under-served buyer pools sit in your backyard: the enormous Gulf expat job-seeker population, and francophone job-seekers (France + francophone Africa) for whom the lettre de motivation is culturally mandatory and English-first tools produce stilted, obviously-translated output.

03 — Product Definition

The core loop

Everything hangs off one canonical Profile JSON extracted from the uploaded CV. Build that schema well and every other feature is just a different view or transformation of it.

1. Upload CV (PDF/DOCX)  →  2. Parse to Profile JSON  →  3. Enhance + ATS score
    ↓
4. Match live jobs (JSearch) with fit scores  →  5. One-click Application Kit per job
    (tailored CV variant · motivation letter · follow-up email · LinkedIn message)
    ↓
6. Chrome extension autofills the application  →  7. Tracker logs it (kanban)

Architecture decision — read this first Do not build on Indeed or LinkedIn directly. Indeed retired its public Publisher API and LinkedIn's is enterprise-only; scraping either violates ToS and gets you blocked. Use an aggregator — JSearch pulls live listings, salary estimates and apply links from Google for Jobs (covering Indeed, LinkedIn, Glassdoor, ZipRecruiter) and supports country codes ae, sa, qa, eg, fr. Same rule for "auto-apply": don't bot-apply on job boards. Do what Simplify does — a browser extension that autofills from the user's profile. Legal, and Chrome extensions are literally your specialty (DropRadar).
04 — Standout Features

What makes it unforgettable

Ship 3–4 of these for v1. The starred two are the moat — do them before anything cosmetic.

🌍

★ Gulf & bilingual mode

EN / FR / AR output, plus a format toggle: Western CV vs. Gulf CV (photo, nationality, visa status, driving licence — the fields Gulf recruiters expect). Zero major player does this. Your single hardest-to-copy advantage.

📦

★ Application Kit per job

Not a generic cover letter. One click = tailored CV variant + motivation letter + follow-up email + LinkedIn DM, all pulled from the same profile so they never contradict each other. Nobody bundles this cleanly.

🎯

ATS score + keyword gap

Paste a JD (or pick a matched job) and see exactly which keywords are missing and where. This is Jobscan's entire $50/mo business as one feature inside yours.

💬

WhatsApp job alerts

Matched jobs delivered via WhatsApp (Twilio / WhatsApp Business API). Email alerts get ignored in MENA; WhatsApp does not. A regional unlock, not a gimmick.

🎤

Interview prep

Generate likely questions from the JD and draft STAR answers from the user's actual resume content. The gap every reviewer flags in Teal and Rezi.

🧩

Chrome extension

Autofill applications from the parsed profile and auto-log every application into the kanban tracker. Reuses everything you learned building DropRadar.

Later additions with proven demand: batch tailoring (paste 5 JDs → 5 tailored CVs), recruiter-outreach generator, salary-negotiation simulator, LinkedIn profile optimizer.

07 — Claude Code + Gemini Workflow

How to actually build it

Two roles, cleanly separated. Claude Code writes the application (schema, serverless routes, UI, extension). Gemini mass-produces content (SEO, translations, marketing copy) from master prompts Claude writes for it. This is your proven PixelForge division of labour.

Step 1 — Give Claude Code the context file

Start every Claude Code session pointed at a CLAUDE.md that pins the stack, the Profile JSON schema, the DB tables, and the API routes. It stops drift and keeps output production-ready instead of scaffold-y.

CLAUDE.md skeleton # CareerForge — build context
Stack: static HTML + Tailwind CDN + vanilla JS on Vercel. Serverless fns for secrets.
DB/auth: Supabase (Postgres, RLS on every table touching resumes).
Models: Gemini Flash = parsing/extraction/matching. Claude Sonnet = enhancement, letters, interview.
Jobs: JSearch via RapidAPI (country codes ae, fr, sa, qa, eg).

## Canonical Profile JSON (single source of truth — every feature reads this):
{ contact, summary, experience[{title,company,dates,bullets[]}],
  education[], skills[], languages[], certifications[], gulf_fields{} }

## Tables: users · resumes · profiles · applications · saved_jobs · kits · credits
## Rules: never expose keys client-side. All AI/job calls via /api/*. Ship complete files, no TODOs.

Step 2 — Build phase by phase with tight prompts

Feed Claude Code one phase at a time (from §06), each as a concrete deliverable. Example for Phase 1:

Claude Code prompt Build the parse → Profile JSON pipeline. A serverless route /api/parse that takes extracted CV text, calls Gemini Flash with a strict JSON-schema system prompt (respond with JSON only, no prose), validates the result, and upserts to the profiles table. Then /api/enhance that takes a profile + target role, calls Claude Sonnet to rewrite bullets with metrics, and returns a diff view. Include the ATS scoring function. Give me every file, complete.

Step 3 — Hand content to Gemini

Once the app works, ask Claude to write a single master prompt that turns Gemini into your content factory:

Gemini master prompt (Claude writes this for you) You are CareerForge's content engine. Produce: (1) landing-page copy for EN + FR, (2) 40 SEO article briefs targeting "CV writing Dubai", "lettre de motivation exemple", "[role] jobs UAE", (3) FAQ schema JSON-LD, (4) AR translations of core UI strings. Tone: practical, outcome-focused, no fluff. Output each as a labelled block.
One non-negotiable Ship the privacy policy + data-deletion flow on day one. Resumes are sensitive personal data, and you'll need those pages for payments and any future AdSense anyway. You already know this drill from FinanceNest and PixelForge.
